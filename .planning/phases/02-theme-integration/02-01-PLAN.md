**1. _variables.scss — Replace Phase 1 stub L/C values with calibrated values**

Read src/scss/_variables.scss first. Replace the OKLCH mastery custom properties in each theme block:

Dark theme (`:root, [data-theme="dark"]`):
```scss
--mastery-bg-L: 35%;
--mastery-bg-C: 0.14;
--mastery-fg-L: 80%;
--mastery-fg-C: 0.16;
```
Rationale: Dark surface is #1e1e32. L=35% cells are subtly colored against it, not glowing. fg at L=80% gives clear contrast. These values were the Phase 1 stubs and are already reasonable — keep as-is.

Light theme (`[data-theme="light"]`):
```scss
--mastery-bg-L: 80%;
--mastery-bg-C: 0.10;
--mastery-fg-L: 28%;
--mastery-fg-C: 0.16;
```
Rationale: Light surface is #ffffff. bg-L=80% produces a light tint (not white, but close). bg-C=0.10 is subtle per locked decision. fg-L=28% is dark text on a light cell — readable. fg-C=0.16 gives the text a hint of hue color.

OLED theme (`[data-theme="oled"]`) — MUST match dark theme values per locked decision:
```scss
--mastery-bg-L: 35%;
--mastery-bg-C: 0.14;
--mastery-fg-L: 80%;
--mastery-fg-C: 0.16;
```
Rationale: OLED surface is #0a0a0a (darker than dark #1e1e32). Per locked decision, OLED uses same L/C as dark. If cells blend too much against near-black, this is a visual calibration issue to note but not change without user input.

High-contrast theme (`[data-theme="high-contrast"]`) — same OKLCH system per user decision (overrides Phase 1 "bypass" decision):
```scss
--mastery-bg-L: 22%;
--mastery-bg-C: 0.18;
--mastery-fg-L: 92%;
--mastery-fg-C: 0.20;
```
Rationale: bg-L=22% on #000 page is a dark colored cell. fg-L=92% is near-white colored text. The L delta of 70% gives approximate WCAG ratio ~10:1 (well above AA 4.5:1). C reduced from Phase 1 stub (0.22 bg, 0.24 fg) to 0.18/0.20 to avoid overly saturated cells that could cause hue-dependent contrast issues.
